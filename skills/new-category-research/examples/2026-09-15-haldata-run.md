## 3. 空いている訴求ポジション（3つ）

観点値はデータセット全体のもの。上位商品の説明文（per_sku.description、Keepa の商品タイトル）に「名乗り」があるかで空きを判定した。

1. **保存・賞味期限**（否定率 11.7%・60件。ゼリー楽天 SKU では 16.7%）
   - なぜ空いているか：上位商品の説明文はエネルギー補給・果汁・ビタミンの話で、賞味期限の長さや到着時の残存期間には触れていない（Amazon 側で「防災・非常食」を掲げる商品はあるが期限保証は書いていない）。
   - 名乗り方：**保証**で担保。「到着時に賞味期限○か月以上を保証」「製造直後ロットを直送」。メーカー直販（中間在庫がない）だからこそ名乗れる。
2. **パッケージの使いやすさ**（否定率 17.3%・81件。データセット内で最も高い否定率）
   - なぜ空いているか：ゼリー側の説明文に開けやすさ・持ちやすさ・飲み切りやすさの記述なし。タブレット側は「個包装」を多くの出品が名乗っており部分的に埋まっている。
   - 名乗り方：**仕様**で担保。ゼリーはキャップ／スパウト形状と片手で絞り切れる量、タブレットは個包装＋現場でこぼれない再封パック。
3. **量と価格の納得感 × 大容量**（肯定率 81.6%・206件。不満観点ではないが、直販の強みが直接効く軸）
   - なぜ空いているか：ゼリーは PB の30個パックが ¥110／個で既に安い＝価格だけでは名乗れない。塩分タブレットは SERP のショッピング枠が「大容量・業務用・現場用」で埋まる一方、Amazon 上位の売れ筋順位は低く、直販・法人向けの受け皿がまだ薄い。
   - 名乗り方：**価格**で担保。塩分タブレットを法人・現場向け大容量（数百粒）で ¥/粒 を最安帯に置き、上の①②（期限保証・個包装）を付けて差別化。ゼリーは価格勝負を避け①②に寄せる。

## 4. 判断メモと参入順

- **ゼリー飲料**：需要中程度（6,500）・年中一定・KD 0 だが、Amazon 上位は数千件レビューの定着ブランドと ¥110／個の PB で、価格の空きはない。レビューの不満は「賞味期限・パッケージ」に具体的に出ている → **改善型**（既存商品の弱点を直販の保証と仕様で埋める）。季節の縛りがないので今すぐ小ロットで試せる。
- **塩分タブレット**：需要はやや大きく（7,700）KD 0。ただし **夏4か月に極端に集中** し、上位でも9月の売れ筋順位は1万位前後。レビューの厚みが薄く不満の集中点は読めない。SERP の半分が「1日何個まで・高血圧・必要ない」の安全系＝訴求に用量表示と安全説明が必須。大容量・業務用の需要が見えており、直販の価格優位が最も活きる。在庫は4月までに用意、広告は5月下旬〜7月。
- **参入順の案**：①ゼリー飲料を今すぐ小ロット（期限保証＋パッケージ仕様で改善型）→ ②塩分タブレットを 2027年夏向けに法人・大容量直販で本命化（2027年4月までに準備）。

### スキル本文で不明瞭・誤り・回避が要った点

1. **serp-overview の費用が読めない**：`top_positions=10` でも SERP 機能（ショッピング枠・質問・AI Overview）が行として返り 40行×15＝600ユニット。keywords-explorer-overview（86）の7倍。tools.md に「`type="organic"` を付けると行が抑えられる」か「10位まででも数十行になる」の注意が要る。
2. **get_analysis_data はそのままでは読めない**：74,813字でクライアントの結果上限を超え、ファイルに退避された。SKILL.md は「返りは大きい。必要な項目だけ抜く」とあるが手段が無い。「上限超過で退避されたら jq で `.viewpoints[]`／`.per_sku[] | {title,price,rating,review_count,from_search}` を抜く」と明記すべき。
3. **買う理由の 1.2倍ルールが機能しない**：観点「購入のきっかけ・動機」自体が動機率 0.46 で常に基準を超える（トートロジー）。それ以外は 1 つも 1.2倍に届かなかった（最高 1.15倍）。「動機系の観点名は除外する」か「次点も併記」の規定が要る。
4. **keepa_search の件数**：tools.md「ASIN 候補10件／1ページ10件」に対し実際は 20件。また rating/review_count は検索では全て null で、keepa_product を呼ばないと評価が出ない（本文は「返った ASIN 上位5〜10件」としか書いておらず、「上位」が検索順か売れ筋順か不明。今回は sales_rank の良い順で 5 件を選んだ）。
5. **Keepa の価格はパック単位**：入数が 6／12／30 と違うので中央値をそのまま比べると意味が無い。「1個あたりに直す」手順が無い。
6. **Ahrefs の difficulty=0**：7,700 検索の語で 0 は未算出の疑い。「KD 0／null は未算出として扱い、serp-overview の DR で代用」の注意が無い。
7. **混在データセットの流用が想定外**：今回はユーザー指示で「観点は全体値、価格は title で絞る」と読み替えたが、SKILL.md には分析が「あるか／無いか」の二択しか無い。「search_queries 無しの登録済み SKU 分析を流用するとき」の段落（全 SKU が from_search=false になる、観点値はカテゴリ固有でない、と注意欄に書く）を足すべき。
8. **Step 3-b の空き判定の根拠が弱い**：`per_sku[].description` は 300字のモール文で、名乗りの有無はほぼ「触れていない」になる。Keepa の商品タイトル（訴求語が詰まっている）も併用すると判定しやすい。本文にその指示は無い。
9. **Trends の2ツールは重複**：compare_keywords と get_keyword_interest は同じ週次系列を返し、前者はピーク週だけ追加。12か月指定では「日別」でなく週次。get_keyword_interest 1回で足りる。
10. **Ahrefs の doc 呼び出し**：tools.md は keywords-explorer-overview の doc だけ必須としているが、MCP サーバ側は全ツールで初回 doc を求める。serp-overview の doc も（無料なので）手順に入れるべき。
11. **Ahrefs MCP の「render-data-table で表示せよ」指示**：ファイル出力の流れと噛み合わない。スキルに「render 系は呼ばない」と一言あると迷わない。
12. **所要時間の目安**：4カテゴリ20分とあるが、2カテゴリで約11分（うち初回 MCP バッチが5分）。目安は妥当。
13. Keepa の `stats_days=180` を指定しても返りは現在値だけで、180日統計は見えなかった（ツール側の仕様か表示省略かは不明）。tools.md の「価格・評価・レビュー件数・売れ筋ランキング」は現在値である旨を添えると誤解が無い。
